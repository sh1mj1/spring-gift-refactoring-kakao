# 주문 흐름 분석

**주문 수량만큼 옵션의 재고를 먼저 줄이고, 주문 금액만큼 회원의 포인트를 차감한 뒤 주문을 저장합니다.** 포인트가 부족하면 주문은 생성되지 않지만, 먼저 줄인 재고는 남을 수 있습니다.

## 1. 주문 관련 키워드

| 범위 | [용어 사전](../../glossary.md)에서 뽑은 용어 |
| --- | --- |
| 주문과 인증 | 주문, 회원, 인증 토큰 |
| 주문 대상과 결제 | 상품, 옵션, 재고, 주문 수량, 상품 가격, 주문 금액, 포인트 |
| 주문과 함께 처리할 수 있는 것 | 선물 메시지, 카카오 알림, 카카오 액세스 토큰, 위시 |

## 2. 코드에서 확인한 흐름

| 순서 | 흐름 |
| --- | --- |
| 1. 요청 확인 | 주문하려는 옵션을 지정하고 주문 수량을 1개 이상 입력해야 합니다. 선물 메시지는 선택입니다. |
| 2. 회원과 옵션 확인 | 인증 토큰으로 회원을 확인하고 주문할 옵션을 찾습니다. 주문은 회원 한 명과 옵션 한 개에 연결되며, 어떤 상품을 주문했는지는 옵션을 통해 알 수 있습니다. |
| 3. 재고 차감 | 주문 수량이 옵션의 재고를 넘으면 중단합니다. 재고가 충분하면 주문 수량을 빼고 그 결과를 저장합니다. |
| 4. 포인트 차감 | **상품 가격 × 주문 수량**으로 주문 금액을 계산합니다. 주문 금액이 1 이상이고 회원의 포인트가 충분하면 해당 금액을 차감하고 저장합니다. |
| 5. 주문 저장과 조회 | 회원과 옵션에 연결된 주문을 저장합니다. 주문 수량과 선물 메시지도 함께 기록합니다. 회원은 자신의 주문만 조회할 수 있습니다. |
| 6. 카카오 알림 | 주문을 저장한 뒤, 주문한 회원에게 카카오 액세스 토큰이 있으면 그 회원 본인에게 카카오 알림을 보냅니다. 선물 메시지가 있으면 알림에 포함합니다. 전송에 실패해도 주문 생성은 성공으로 처리합니다. |

## 3. 개념과 규칙

| 구분 | 확인한 내용 |
| --- | --- |
| 코드에 있는 개념 | **주문 금액**은 포인트를 차감할 때 계산하는 값으로 존재합니다. **위시**는 회원과 상품을 연결하는 별도 기록으로 존재합니다. |
| 코드에 없는 개념 | **주문 당시 금액을 보존하는 기록**과 **주문한 회원과 별도로 지정하는 선물 수신자**는 주문에 없습니다. |
| 코드에 드러난 규칙 | 주문 수량은 1개 이상이고 재고 이하여야 합니다. 주문 금액은 1 이상이고 회원의 포인트 이하여야 합니다. 카카오 알림의 성공 여부는 주문 생성 결과에 영향을 주지 않습니다. |
| 코드에 드러나지 않은 규칙 | **주문 실패 시 재고와 포인트를 함께 되돌리는 규칙**이 구현되어 있지 않습니다. 포인트 차감에 실패하면 줄어든 재고가 남을 수 있고, 주문 저장에 실패하면 줄어든 재고와 포인트가 모두 남을 수 있습니다. **주문한 상품을 위시에서 제거한다**는 단계는 주석에만 있습니다. |

주문 당시 금액의 보존 여부를 확인하기 위해 저장 구조를 한 차례 추가로 확인했습니다. 관련 코드와 저장 구조 13개 파일을 기준으로 분석했으며 서버에서 실제 요청은 실행하지 않았습니다. **범위 밖**은 카카오 로그인과 토큰 발급, 위시의 독립적인 사용 흐름, 상품·옵션 관리, 동시 주문입니다.
